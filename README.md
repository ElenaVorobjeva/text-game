# Тихий хороший день

Небольшая текстовая игра о мягком ритме жизни, простых решениях и спокойном дне.

Игрок проходит три главы, выбирая реплики и действия. Каждый выбор меняет три характеристики —
**Забота**, **Связь**, **Покой** — и от их соотношения зависит, какой концовкой закончится день.

## Стек

- React 19 + TypeScript
- Vite 8
- Tailwind CSS v4 (токены дизайн-системы в `@theme`)
- react-router (HashRouter)

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
```

Остальные команды:

```bash
npm run check       # всё сразу: типы + линт + формат + тесты
npm run build       # check + продакшен-сборка в dist/
npm run preview     # локальный просмотр собранной версии

npm run typecheck   # tsc -b
npm run lint        # eslint
npm run format      # prettier --write (переформатировать)
npm run format:check # prettier --check (только проверить)
```

`npm run check` — то, что стоит запускать перед коммитом: он же встроен в `build`.

## Как устроен контент

Вся игра описана декларативно в `src/data/gameData.json` — код сцен не содержит.
Сейчас это 3 главы по 3 сцены и 4 концовки.

Сцена состоит из текста и списка вариантов. У варианта есть `nextSceneId`, необязательные
`conditions` (когда вариант вообще показывать) и `effects` (что произойдёт при выборе):

```json
{
  "id": "chapter1_scene1",
  "chapter": 1,
  "title": "Пробуждение",
  "text": "Утро мягко просачивается сквозь занавески…",
  "choices": [
    {
      "id": "c1_s1_choice1",
      "text": "Остаться в постели и прислушаться к утру",
      "nextSceneId": "chapter1_scene2",
      "effects": [
        { "type": "change_stat", "stat": "calm", "delta": 1 },
        { "type": "set_flag", "key": "started_slowly", "value": true }
      ]
    }
  ]
}
```

**Условия:** `flag` (значение флага), `stat_gte` (характеристика не ниже порога),
`has_item` (предмет в инвентаре). Вариант без условий доступен всегда.

**Эффекты:** `change_stat`, `set_flag`, `add_item`, `remove_item`.

**Концовки** — это сцены с `"chapter": 0`, `"isEnding": true` и пустым списком выборов.
Развилка к ним собрана в последней сцене третьей главы: три «сильные» концовки открываются
условием `stat_gte` со значением 5 по соответствующей характеристике, а `ending_balanced`
доступна всегда и работает как запасной вариант.

Чтобы добавить сцену, достаточно дописать объект в `scenes` и сослаться на его `id` из
`nextSceneId` любого варианта — трогать компоненты не нужно.

## Тесты

Тесты на [Vitest](https://vitest.dev/). Запуск:

```bash
npm run test      # watch-режим, для работы
npm run test:run  # однократный прогон, для CI и npm run check
```

`npm run test` без подкоманды остаётся висеть и следить за изменениями — в скриптах и CI
нужен именно `test:run`.

Тестовые файлы лежат **рядом с проверяемым модулем**, а не в отдельной папке:

```
src/engine/conditions.ts
src/engine/conditions.test.ts
src/engine/effects.ts
src/engine/effects.test.ts
```

Так их подхватывает и Vitest (дефолтный glob `**/*.{test,spec}.ts`), и `tsc -b` — в
`tsconfig.app.json` указано `"include": ["src"]`, поэтому тесты за пределами `src/`
остались бы без проверки типов. В сборку они не попадают: Vite бандлит только то, что
достижимо от точки входа.

Что покрыто:

- `engine/conditions.test.ts` — доступность вариантов: `flag`, `stat_gte`, `has_item`,
  объединение условий по И, граница `>=`
- `engine/effects.test.ts` — применение последствий: все четыре типа эффектов, порядок
  применения, иммутабельность состояния
- `engine/gameEngine.test.ts` — переходы между сценами, разблокировка глав и концовок,
  подбор картинки, ошибки на несуществующих сценах
- `utils/saveLoad.test.ts` — сохранение и загрузка, поведение при испорченном JSON
- `data/gameData.test.ts` — целостность контента: все ссылки на сцены существуют, нет
  недостижимых сцен и тупиков, пути к картинкам ведут на `/images/`
- `app/App.test.ts` — навигация: маршруты, редирект с `/game` без сохранения, кнопка
  «Назад» по истории (Testing Library + `MemoryRouter`)

Соглашения: названия тестов (`describe` / `test`) на английском, комментарии внутри — на
русском. `expect` и `test` импортируются явно из `vitest`, без `globals: true` — поэтому
отдельный конфиг Vitest не нужен, а типы в тестах проверяются наравне с остальным кодом.
`saveLoad` подменяет `localStorage` заглушкой в памяти; тестам навигации DOM включается
пофайлово докблоком `// @vitest-environment jsdom`, так что тесты логики его не поднимают.

Ещё не покрыто: остальные компоненты по отдельности и сквозные сценарии в браузере.

## Сохранения

Прогресс пишется в localStorage под ключом `quiet-good-life-save` после каждого выбора.
При наличии сохранения главное меню показывает «Продолжить», иначе — «Старт».
